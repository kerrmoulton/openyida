# 节点表达式的运行时类型边界

配置节点表达式和输入参数时，分别确认源字段、消费位置和目标参数的契约。表单组件的类型声明、变量查看接口的展示格式、节点实际收到的值属于不同层次，不能相互替代。

## 类型与转换

- 组件 Schema 描述字段的编辑结构；经过序列化、参数绑定或表达式求值后，值的表示形式可能改变。
- 集合类型、集合的 JSON 文本和单个标量是不同的输入。数组操作要求实际数组，不能只依据组件声明推断。
- 转换应由源值与目标参数的契约决定，显式处理解析失败、类型不匹配及集合基数；通用工具不替应用选择集合中的某一项。
- 缺失值、`null`、空字符串和空集合分别处理，不能未经接口契约确认就合并为一种状态。
- 标识和编码保持文本语义，不能因为内容看起来像数字而自动转为数字。某种函数存在隐式转换，不代表其他函数也支持相同转换。

## 静态校验的边界

`node-expression` 校验区分字段来源与显式数组来源，对缺少可靠数组类型依据的取值操作报错。校验以 Schema 元数据为依据；缺少元数据时，只对已支持的标准字段采用保守规则。

数组构造表达式、数组产生函数和上游节点输出分别遵循各自契约。不能因为表达式包含某类字段引用，就把整个表达式统一视为该字段的原始类型；字符串字面量中的相似文本也不参与字段类型判断。

静态检查不会自动重写表达式、选择集合元素或改变流程分支。具体支持范围以校验实现为准，未覆盖的消费位置不能据此宣称类型已验证。

## 运行验证的边界

首次接入或改变取值方式时，核对目标节点实际输入、输出及结果，覆盖正常值、空值、集合值和异常值。查看接口中的序列化字符串不能单独证明运行时参数类型。

编译、保存、回读和实际执行分别报告。静态校验通过只代表通过静态检查；`runtime: not_run` 不得表述为运行通过。一个消费位置的验证结果不能直接推广到其他节点或执行环境。
